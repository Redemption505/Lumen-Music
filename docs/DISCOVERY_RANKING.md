# 内容发现：排序与推荐核心

`service/lumen_service/discovery.py` 提供纯本地排序和基于真实搜索结果的推荐。此模块不发起新的网络协议请求、不保存个人数据，也不构造伪造曲目。

## 搜索相关性

`rank_tracks(query, tracks, *, rerank=True, kind="all") -> tuple[Track, ...]` 保留所有输入候选。`rerank=False` 原样保留数据源顺序；开启时按下面的元数据评分排序，最终相同分数保持稳定顺序。`kind` 接受 `all`、`single`、`collection`，只影响评分，实际分 P 筛选由 API 完成。

关键词先按空白切分，忽略大小写与标点，再去重。设唯一关键词数为 N、在标题或作者中命中的词数为 H，评分为：

`240 × H/N + 关键词匹配分之和/N + 短语分 + 时长分 + 版本分 + 4/(原始位次+1)`

- 关键词匹配分：每词与完整标题相同 +100，否则标题包含 +22；与完整作者相同 +34，否则作者包含 +15。标题与作者分可以累加。
- 短语分：按唯一关键词原顺序拼接，与完整标题相同 +120，否则标题包含整段 +55；与完整作者相同再 +50。标题长度不扣分，重复查询词不重复计分。
- 时长分：90–480 秒 +12，超过 900 秒 -20，其余及未知时长为 0。查询明确含「合集、串烧、歌单、专辑、collection、playlist、album」，或 `kind="collection"` 时，时长分为 0。
- 版本分：未主动搜索版本词时，翻唱、现场、Live、伴奏、混音等版本 -32，原唱、原曲、官方等 +10。用户明确搜索版本时不施加版本调整。`kind="collection"` 解除合集与串烧标签降权，但不解除普通查询中的翻唱、现场等降权。
- 原始位次从 0 起，只提供最多 4 分的弱先验，保留元数据相同时的上游顺序。

覆盖率是主要相关性信号，时长和上游位次只辅助排序。排序只依据可观察元数据，不能验证视频实际音频是否为原曲。BV 直达完全绕过此排序，保留分 P 顺序。

## 推荐闭环

`build_taste_profile(library_snapshot, history_snapshot)` 从收藏、歌单和有效听歌记录提取偏好。收藏计 4、歌单出现计 2、有效播放按次数计权（每首最多取 5 次），因此近期常听歌曲的作者会进入前列。当前格式不包含可直接用于分析的细粒度时间序列，推荐不声称捕获近期变化。

`recommend(provider, library_snapshot, history_snapshot, *, intent_generator=None, limit=20) -> RecommendationResult` 按以下流程执行：

1. 用本地偏好生成作者与代表歌曲检索词；无个人数据时使用「热门音乐」「华语音乐」作为冷启动检索词。
2. 可选的 `intent_generator(TasteProfile)` 返回一个检索词或最多 5 个检索词。生成器异常或没有有效输出时回退到本地检索词。AI 服务可接入这一接口，但本模块本身不调用 AI，也不保存密钥。
3. 对每个检索词调用 `provider.search` 获取真实曲目，按相同相关性规则、上游位次及偏好权重重新排序，按 BV 与分 P 身份去重，再用作者均衡安排前列结果。偏好附加分为作者权重 ×2；已有听歌记录的曲目 -12。作者均衡优先为每位作者安排至多两首，再补入剩余候选。

返回对象包含 `tracks`、`intents`、`failed_intents` 和 `cold_start`。单个上游检索失败时保留其他检索词的真实结果并报告失败词；所有检索词都失败时保留第一个上游异常交给 API 层返回清晰错误；检索成功但没有候选时返回空集合。结果不应被描述为 AI 直接生成的歌曲。

测试文件为 `service/tests/test_discovery.py` 与 `service/tests/test_discovery_http.py`，覆盖原曲与明确版本搜索、去重覆盖率、短语及长标题、时长与显式合集、稳定顺序和关闭重排、BV 分 P 顺序、HTTP 参数校验，以及听歌记录权重、AI 意图接真实候选、回退、冷启动和上游失败。
