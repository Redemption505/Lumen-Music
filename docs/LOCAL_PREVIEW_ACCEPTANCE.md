# Windows 本地优先测试版验收

更新：2026-11-18。[v0.2.2-preview.1](https://github.com/Redemption505/Lumen-Music/releases/tag/v0.2.2-preview.1) 已发布为 Windows x64 便携测试版，实际构建为 `lumen-0.2.2-local-20261106.1`。发行身份、附件及源码验证见[公开测试版与验收范围](PUBLIC_PRERELEASE_READINESS.md)。

## 1. 当前结果与验收边界

11月13日完成本轮**基本双缩放窗口、播放和正常退出**验收。运行的是同一独立镜像，候选786个文件在运行前后均与清单同字节；未改产品源码、BuildId、日用安装或标准发行ZIP。

| 项目 | 实际结果 |
| --- | --- |
| 125%窗口与播放 | 本地测试版标识、首页、本地页及文件夹导入通过；导入1首8秒合成WAV，观察到播放进度与同步LRC。沉浸页进入/返回、迷你窗口歌词及返回通过 |
| 150%窗口与播放 | JVM实际缩放日志确认1.5；首页恢复同一队列并保持暂停，恢复播放及沉浸歌词显示通过。已观察页面未见阻断操作的截断；未扩展为全部主题、尺寸和弹窗矩阵 |
| 实际声音 | 用户明确确认“听到了，声音正常”。使用合成音频，不播放个人曲目，不以界面进度替代声音证据 |
| 正常退出 | 两档均正常关闭；捆绑JVM/Python/代理身份及健康检查通过，应用退出码均为0，自有进程停止、两个本轮监听端口释放 |
| 资料恢复与隔离 | 同一隔离资料跨窗口/缩放沿用，保留1首测试曲和队列；未清空资料以恢复状态，未访问私人曲库 |
| 三个重启后首次启动 | 仍为0/3。本轮为同一Windows会话的普通启动，不计为重启首启或三份新资料样本 |
| 独立电脑、原闪退者复测 | 独立设备暂无条件。维护者同意先做本机模拟，原设备和原闪退者仍无复测 |
| VLC Win64 重链接验证 | 构建输入及补丁已核对，完整编译、修改静态依赖后的重链接和替换播放待验 |
| 发布形态 | 已公开便携 ZIP。独立安装器、升级和卸载属于日用安装版验收范围 |

实际JVM日志分别记录 `Forcing UI scaling factor: 1.25` 与 `1.5`，未修改系统显示设置。两档窗口句柄首次观测为4.61/5.73秒，探针就绪为10.35/11.96秒；后者包含服务、进程及端口核对，不是纯渲染或单独计时的UI响应。样本沿用同一资料，不能据此宣称冷启动性能改善。

首次尝试因私有探针仍检测旧进程名而漏记Preview窗口，并出现文字树与截图不一致，已停止输入并由用户正常关闭，失败证据保留。探针改为按实际EXE名称检测、显式显示测试窗口并激活新返回窗口后，双缩放复验通过；没有放宽启动/健康/退出断言。截图错配的单独根因未证实。原记录的 `firstProfile` 字段只检查 `library.json`，不可靠，不能拿它将本轮重试写成全新资料首启。

11月18日从便携 ZIP 解压到带空格和中文的新目录，校验1,917项内容与5个关键 x64 二进制。用隔离的空资料和仅系统目录的 `PATH` 启动包内 Python 服务，在线策略拒绝、本地收藏及歌单跨服务重启、备份导出与预检通过，测试端口已释放。

## 2. 便携 ZIP 的原生窗口补验

11月18日从便携 ZIP 的实际解压目录启动，以隔离资料及合成音频通过以下操作。

1. 重复导入去重、本地搜索、暂停与拖动，以及公开版在线入口的禁用说明。
2. 收藏与普通歌单写入后关闭应用，重新打开仍能看到收藏、歌单及其中的测试曲。150% 迷你窗口返回主窗口通过。
3. 在设置页导出备份，预检显示 1 首收藏、1 个歌单、1 条听歌记录。取消正式恢复后正常退出，校验 ZIP 成员和退出后资料一致性。

11月6日的LRCLIB单曲HTTP查询收到合法JSON但返回0候选，只验证传输；11月13日使用本地合成LRC，没有重复公网查询，也不证明真实歌曲歌词匹配。

公开附件的 SOURCE、NOTICE 和 SHA-256 已另行核对。重启首启、独立电脑及 VLC 完整编译与重链接保留待验。

## 3. 三个重启会话的最小安排

沿用[启动方案](STARTUP_ACCEPTANCE.md)的时间字段、样本数和失败保留原则，每次约3–5分钟；重启由用户安排，可分多次自然重启完成。

更新后的私有工具位于 `build/windows-prerelease-20261118/reboot/`：

- `reboot-campaign.json` 绑定新候选BuildId与主JAR哈希，当前只为 `prepared-not-started`；没有记录成功样本。
- `start-after-reboot.ps1` 拒绝准备前的系统会话、同一boot重复尝试或改变候选；首次启动需操作者确认自本次重启后尚未运行该候选。该确认是事实记录，**不代替当次输入接管安排**。
- `native-preview-probe.ps1` 已接入按实际 EXE 检测、可见启动及已存在资料文件识别的修正版。入口已通过语法、候选身份初始化和拒绝未确认首启的预检。真实重启采样为 0/3。
- `write-preview-marker.ps1` 记录真实切页前后与关闭动作时刻；标记包含工具调度开销，不把观察上界称为纯渲染时间。

每次保存启动、窗口、界面可操作、服务/代理、正常退出时间及自有资源释放结果。原样记录失败/未完成；同一会话重试可用于诊断，但不能新增一个重启样本。三个不同真实会话完成后，才把真实记录填入[CSV模板](templates/startup-runs.csv)，用现有 `startup-report.py` 汇总，不补造未观察字段。

## 4. 独立设备可用时的一批操作

一台无开发工具的 Windows 10/11 x64 电脑即可开始。按[便携版指南](WINDOWS_GUIDE.md#公开便携测试版)下载并解压，完成导入、搜索、播放和拖动、收藏歌单、备份预检及退出重开，约 15–20 分钟。使用[反馈模板](FRIEND_FEEDBACK.md)记录实际版本、BuildId、系统和缩放；按便携解压运行记录覆盖。

反馈只需复现步骤及必要的脱敏证据。独立设备目前暂无结果。
