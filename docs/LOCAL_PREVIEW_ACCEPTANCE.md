## 2. 下一批窗口操作，约10分钟

条件：至少约2 GiB可用物理内存且短暂稳定，其他任务不自动操作桌面；重新安排本轮鼠标键盘接管。使用独立合成音频/歌词和资料，不访问私人曲库。会实际播放短合成音，提前明确；全程不自动重启。

1. 从独立 `LumenMusicPreview.exe` 启动，确认“本地测试版”标识和新BuildId、首页/本地页可操作；B站搜索/BV解析/在线发现/电台/收藏夹导入不可用且解释清楚。
2. 导入测试文件夹并重复导入，检查去重、本地搜索、收藏和歌单；播放/暂停/拖动合成WAV及显示同目录合成LRC。旧在线元数据可整理、删除/备份，但不播放或自动加载在线封面。
3. 切换125%/150%，检查页头、按钮和说明不截断；进入沉浸及迷你窗口并返回。按当前使用方式保留同一profile，不靠清空资料恢复状态。
4. 导出备份并预检、关闭重开核对状态；正常关闭后确认桌宠、捆绑子进程和监听端口释放。核对默认资料只写入 `%LOCALAPPDATA%/Lumen Music Local Preview`，日用两个资料目录未被候选使用。

这批通过后才决定是否制作独立安装候选及最终分发归档；它不自动提供独立电脑或重启证据。真实LRCLIB查询如另行验证，只用一首合适样本、限制调用次数，不把离线mock测试当网络可用性。

## 3. 三个重启会话的最小安排

沿用[启动方案](STARTUP_ACCEPTANCE.md)的时间字段、样本数和失败保留原则，每次约3–5分钟；重启由用户自行安排，可能分多次自然重启完成。先完成上批工具与窗口校验，避免在重启后临时修驱动、混入开发环境。

准备好的私有工具位于 `build/public-prerelease-followup-20261106/`：

- `reboot-campaign.json` 绑定新候选BuildId与主JAR哈希，当前只为 `prepared-not-started`；没有记录成功样本。
- `start-after-reboot.ps1` 拒绝准备前的系统会话、同一boot重复尝试或改变候选；首次启动需操作者确认自本次重启后尚未运行该候选。该确认是事实记录，**不代替当次输入接管安排**。
- `native-preview-probe.ps1` 沿用已有窗口/健康/所有权/QPC与退出观察，改为独立Preview程序和local健康身份；同一 `campaign-profile` 跨会话沿用。当前只做了语法/准备路径核对，尚无新原生运行结果。
- `write-preview-marker.ps1` 记录真实切页前后与关闭动作时刻；标记包含工具调度开销，不把观察上界称为纯渲染时间。

每次保存启动、窗口、界面可操作、服务/代理、正常退出时间及自有资源释放结果。原样记录失败/未完成；同一会话重试可用于诊断，但不能新增一个重启样本。三个不同真实会话完成后，才把真实记录填入[CSV模板](templates/startup-runs.csv)，用现有 `startup-report.py` 汇总，不补造未观察字段。

## 4. 独立设备可用时的一批操作

一台无开发工具的Windows电脑即可开始，按[朋友试用说明](FRIEND_TRIAL.md)完成15–20分钟核心流程并填[反馈模板](FRIEND_FEEDBACK.md)，不要求先凑齐多人。以最终拟公开形态验收：有安装器就验安装/卸载；只有便携包就如实记为解压运行，保留安装门槛未覆盖。先填实际版本、BuildId、系统和缩放，再记录问题。

不需要发送完整曲库、媒体、Cookie或备份。当前没有自动联系朋友、上传材料或安排后台定时检查；环境未具备时保持明确待验。
