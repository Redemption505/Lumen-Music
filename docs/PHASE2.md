# 第二阶段目标：从可播放原型到日常使用的音乐播放器

第二阶段保留 JavaFX 桌面端与个人曲库，重点完善在线播放、内容发现和日常交互。在线音轨优先由 VLC 经 Axum Range 代理流式播放；不支持可靠跳转的音轨在拖动后自动转为完整文件播放。

## 现有基础与增量

第一阶段已有 B 站视频搜索、BV/分 P 身份字段、收藏与歌单、手动排序、播放队列、循环模式、封面、手选及本地 LRC、音量、深浅主题和 Windows 启动/安装包。当前已增加内容发现、桌面侧栏、持久音频缓存设置、Axum Range 侧车和 VLC 播放器。

## 建议实施顺序

1. **播放与数据底座**：[当前实现与限制](PHASE2_FOUNDATION.md)：有效听歌记录、持久缓存与备份已接入；在线播放优先使用 VLC 流式播放，必要时回退到 JavaFX 完整文件播放。
2. **内容发现**：[已实现并验证的范围与限制](PHASE2_DISCOVERY.md)：BV 直达、单曲/合集筛选、相关性重排、听歌记录驱动推荐，以及可选 AI 检索意图接真实候选和本地重排。
3. **曲库与歌词**：[已实现并验证的范围与限制](PHASE2_LIBRARY_LYRICS.md)：公开收藏夹导入、拖拽排序、备份恢复和自动歌词；专项覆盖数据恢复、失效条目及歌词误匹配。
4. **完整桌面体验**：[桌面能力与验证范围](PHASE2_DESKTOP.md)：左侧导航、首页推荐卡片、底部播放条、沉浸页、四档主题、原生标题栏、迷你播放器、Windows 任务栏控制和桌宠；所有视图共享同一播放状态。

## 技术决策与边界

- Python 保留搜索、合集元数据、AI 意图、音频地址解析和个人数据；`stream-proxy/` 的 Rust Axum 侧车负责转发音频 HEAD/Range。VLC 负责在线流式播放，本地文件与不兼容的在线进度跳转由 JavaFX 播放。
- 默认无需账号登录，也不要求用户提供账号 Cookie；搜索和取流仍取决于 B 站游客接口及资源可用性。“没有封号顾虑”不作为可保证的验收结论。
- AI 设置可在桌面界面编辑；非敏感值保存在 `ai-settings.json` 并进入备份，密钥独立存于 `ai-secret.json` 且不进入备份。无 AI 配置时，基础搜索、播放和曲库仍可用。
- 桌宠形象、背景图、歌词和其他素材进入公开仓库前须确认使用权；第一阶段测试音频不随源码分发。
