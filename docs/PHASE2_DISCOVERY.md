# 第二阶段第二步：内容发现

首页、搜索和播放队列已接通。搜索可输入关键词、裸 BV 号或标准 B 站视频链接；BV 直达会展开并显示分 P；用户双击结果后才按页码组成队列，完整结果直接复用，不再次向 B 站展开。搜索栏可选“全部 / 单曲 / 合集”，其中单曲指 `partCount=1`，合集指 `partCount>1`，与标题是否含“合集”无关。

## 数据与排序

普通搜索先取得 B 站游客接口的真实候选，再按标题、UP 主、关键词覆盖与版本词做稳定的本地重排。未主动搜索翻唱或 Live 时，原曲及官方版上浮。排序只依据元数据，不能验证音频内容。B 站搜索响应当前通常不含分 P 数；选择单曲或合集时，服务会对排序靠前的至多 12 个视频逐一查询较轻量的分 P 列表。无法核实的条目不会被误归类，响应的 `unresolvedCount` 告知核实失败数量。普通“全部”搜索不增加这些详情请求。

BV 直达优先读取视频详情；详情接口拒绝游客请求时，以分 P 列表构造可播放身份、时长与顺序。此时曲名采用分 P 标题，UP 主和封面可能暂缺。视频已失效或两个接口均不可用时，界面显示错误，不切换当前队列。

## 听歌记录与推荐

JavaFX 实际播放、暂停、拖动、切歌和结束时向 `/api/listening` 发送同一会话的采样；Python 服务用单调时钟核实有效听歌时长并写入版本化记录。首页手动刷新推荐。收藏权重 4、歌单出现权重 2、有效播放权重按次数计入，先生成检索词，再向真实数据源取候选，按相同本地规则重排、去重并平衡作者。冷启动使用通用音乐检索词；演示源可展示其三首虚构曲目。

侧栏“设置 → AI 推荐”可保存模型、HTTPS Chat Completions 地址与密钥；未保存应用内设置时也可使用 `LUMEN_AI_CHAT_COMPLETIONS_URL`、`LUMEN_AI_MODEL` 和 `LUMEN_AI_API_KEY`。模型生成最多四个短检索词，并可对真实候选 ID 重排；候选与播放地址仍来自真实数据源。未配置、请求超时或结果无效时回到本地检索/排序。非敏感设置可随数据备份；密钥独立存放且不进入备份。当前画像数据边界与一句话输入见[第三阶段说明](PHASE3.md)。目前以模拟模型响应和真实本机 HTTP 验证候选闭环，未对付费服务发起调用。

## 验收与限制

确定性测试覆盖搜索排序、过滤、BV 多 P、详情受拒后的分 P 回退、听歌采样及记录驱动推荐。真实 B 站 HTTP 测试验证了“周杰伦 官方MV”搜索、单曲筛选与 BV 直达；JavaFX 演示窗口实际完成加载、队列切换、循环和关闭，另用完整播放演示音频确认有效记录真实写入。在线音频优先由 VLC 经 Axum 代理流式播放；拖动失败的音轨使用完整会话文件恢复进度。

单曲/合集筛选需要额外访问 B 站，可能明显慢于“全部”，且只核实本次搜索前 12 个候选。B 站游客接口可能变动或拒绝请求；`unresolvedCount` 非零时结果并不代表所有候选均已分类。推荐没有按个人历史做在线模型训练，也不会凭空生成歌曲。
