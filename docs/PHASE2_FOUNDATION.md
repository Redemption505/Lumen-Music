# 第二阶段第一步：播放与数据底座

当前底座包括有效听歌记录、持久音频缓存、备份恢复、Rust Axum 音频侧车和 VLC 在线播放器。真实 B 站音轨默认通过 Range 代理流式起播；部分音轨远距离 seek 不可靠，拖动后会改用完整文件播放。

## 有效听歌记录

时长 1–59 秒的短歌须在同一播放会话中听满 90%；时长不少于 60 秒的长歌须累计 30 秒；未知时长不计。每次播放会话最多计一次，重播创建新会话。以单调时钟与媒体位置增长的较小值累计有效秒数；暂停、拖动和异常位置跳跃不计。分 P 使用独立曲目 ID。版本化 `history.json` 按曲目聚合播放次数、上次播放时间和有效时长，原子写入并保留前一有效状态。完整字段与调用契约见 [听歌记录格式](PLAY_HISTORY_FORMAT.md)。

`ListeningSession` 和 `HistoryStore` 核算采样；桌面端的 `ListeningReporter` 按播放、暂停、拖动和结束事件向服务提交采样，达到阈值后写入记录。推荐可使用有效记录。

## 持久音频缓存

`PersistentAudioCache` 默认关闭；用户在侧栏“音频缓存设置”中启用后，可设置容量上限、查看占用和条目数、清空缓存。缓存按最近使用淘汰，重启后恢复；曲目 ID 经 SHA-256 转为文件名，只在完整下载并校验后提交，损坏条目不参与播放。在线播放链路已接入该缓存。

`OnlineAudioCache` 使用会话临时文件，并在用户启用时复用持久缓存中已完成的音轨。默认在线播放无需完整下载；启用缓存时在后台保存完整音轨，不阻塞起播。不支持可靠远距离拖动的资源会使用会话文件恢复目标进度。

## 数据备份 ZIP v1

格式包含必需的 `manifest.json` 与 `library.json`，可选 `history.json`、经过白名单筛选的 `ai-settings.json` 和一张背景图。清单逐文件记录大小及 SHA-256；不包含音频缓存、账号 Cookie 或 AI 凭据。非敏感 AI 设置保存在 `ai-settings.json`，密钥独立存于 `ai-secret.json`，不会导出。后端提供原子导出、只读导入预检及完整预检后的恢复；桌面端在恢复前展示预览。详细规则见 [备份格式](BACKUP_FORMAT.md)。

预检只验证备份可读，不会修改用户数据；用户在界面确认恢复后，服务重新校验并写入备份内容。可选文件未包含时保留原状。

## Range 转发与播放边界

Python 负责解析 B 站音频地址；`stream-proxy/` 的 Rust Axum 侧车由 Windows 打包脚本带入分发目录，并由 `LumenLauncher` 启动或复用，转发音频 HEAD 与 Range 请求。以下检查针对真实 B 站音轨；VLC 3.0.23 与 JavaFX 21.0.12 在 Windows 上运行。

| 检查 | 实测结果 |
| --- | --- |
| Axum 侧车音轨预检 | `HEAD 200`，`Content-Type: audio/mp4`，总长度 6,201,843 字节。 |
| Axum 侧车远端 Range | `bytes=1048576-1114111` 返回 `206`，`Content-Range: bytes 1048576-1114111/6201843`。 |
| JavaFX 经侧车播放 | 真实 B 站音轨完整下载到会话文件后播放，进度拖动可用。 |
| JavaFX 直连代理 seek 实验 | 目标 80.851 秒；5 秒后位置仅 5.420 秒，远距离 seek **未生效**。 |
| VLC 直连 Axum 代理 | BV1BZbSzZEGT 可在未完整下载时起播，跳到约 80.851 秒，5 秒后位置约 82.901 秒；暂停、恢复与切歌实验通过。 |
| 主窗口在线拖动 | 同一 BV 样本流式拖动通过；BV1nnWFzGEJQ 的原生 seek 失败后自动下载完整文件并恢复到目标进度。 |

侧车具备正确的单段 Range 响应。JavaFX 对 DASH 分段 MP4 直连时不能稳定跳转，因此在线链路改用 VLC。VLC 也不能保证每个 B 站音轨都可原位跳转；播放器会检查拖动后的实际位置，必要时下载完整音轨并使用 JavaFX 恢复。关闭窗口会释放两套播放器和由窗口启动的本地服务。

## 合集连播

`Track` 保留 BV 号与分 P 页码，曲目 ID 使用 `bilibili:BV号:p页码`；`PlayerQueue` 保留独立快照和重复模式。BV 直达会展开全部分 P；普通搜索中选中合集时，桌面端通过 `GET /api/collections/{BV}/tracks` 取得按页码排序的分 P 并入队。已用 50 P 周杰伦合集核对分 P 顺序及 UI 队列标题；播放结束推进、手动切歌和循环模式沿用队列策略。
