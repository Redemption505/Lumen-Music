# 第三阶段：应用逻辑结构与功能优化

本文保留前期逻辑与功能优化的范围说明。以 v0.1.1 歌词修复版为基线的后续开发，统一见[第三阶段：拓展与整合](PHASE3_EXPANSION.md)。下文各步的验收与限制属于对应实施时期，当前发行行为以 README 为准。

## 第一步：游客取流与搜索质量

参考 [bili-music 技术亮点](https://github.com/Jmiao11/bili-music/tree/master)，结合已有 JavaFX、Python、Axum 分层实现，优先补齐已确认的缺口。

| 参考能力 | 当前采用方式 |
| --- | --- |
| 免登录游客取流 | Python 使用游客 CookieJar，通过 nav 获取 WBI 密钥，签名请求 `/x/player/wbi/playurl`，沿用 AAC-LC 音轨、备用 CDN、60 秒直链缓存及 Range 代理 |
| 游客搜索补票 | 同时检查非空、未过期的 buvid3 和 buvid4；首页缺任一项时调用 SPI 补齐，保留已有有效票据。搜索返回 v_voucher 或风控业务码时重建游客身份并重试一次，持续拒绝明确报错 |
| 搜索展示与队列解耦 | 复用已有 searchResults 与 PlayerQueue 独立快照，搜索不启动播放 |
| 切歌不串台 | 复用 loadVersion、collectionVersion、下载取消及媒体事件身份检查 |
| 多 P 连播 | 继续以 BV + 分 P 作为独立 Track 身份，展开后进入已有队列；不另加参考项目的旁挂游标 |
| 本地原子写入 | 复用曲库、听歌记录的同目录临时文件、fsync、原子替换及备份；损坏数据不重置为空 |
| AI 真实候选推荐 | 复用模型只生成检索意图、Provider 获取候选、本地重排和去重的链路；模型输出不能直接创建推荐曲目 |
| 本地相关性重排 | 以去重关键词覆盖率为主信号，结合精确/短语匹配、时长、版本和弱上游位次先验；明确搜索合集时解除单曲时长倾向 |

### 游客接口

`providers.py` 负责游客身份与 WBI 密钥，`wbi.py` 负责纯签名算法，`streaming.py` 负责分 P 的 CID 选择、音轨解析和字节转发。WBI 密钥在服务实例内缓存一小时；签名含当前时间戳，拒绝时至多刷新一次密钥并重新签名。游客 nav 返回 `-101` 但带有效 `wbi_img` 时仍可获取密钥。

游客票据保留在线程独立的 CookieJar 中，避免并发请求共享可变网络会话。当前不读取账号 Cookie，也不新增 yt-dlp 依赖。冷请求可能需要首页、SPI、nav 等额外请求；参考项目的首播数字不是本项目的性能指标。

参考算法与接口行为来自 [WBI 模块](https://github.com/Jmiao11/bili-music/blob/master/src-tauri/src/wbi.rs)和[游客取流模块](https://github.com/Jmiao11/bili-music/blob/master/src-tauri/src/guest_playurl.rs)，使用 Python 标准库独立适配。

### 搜索接口

`GET /api/tracks` 接受 `rerank=true|false`，默认 `true`。Java MusicClient 默认入口显式传 `true`，也提供布尔重载；关闭时保留上游顺序。BV 直达不做相关性排序，始终按分 P 顺序返回。筛选仍依据真实分 P 数，时长只影响排序。完整公式与边界见[排序规则](DISCOVERY_RANKING.md)和[接口契约](API.md)。

### 验收与边界

2026-09-28：Python 全套 151 项运行，149 项通过、2 项默认跳过的在线测试；随后补充 HTTP 风控拒绝刷新测试，最终游客/WBI/取流定向 46 项运行，44 项通过、2 项跳过。Java DiscoveryClientTest 3 项通过，包含实际本机 HTTP 参数检查。定向测试覆盖单项缺票、过期票、票据发送、标准签名向量、密钥缓存/过期/刷新、持续风控、CID 分 P 选择和搜索排序开关。

隔离临时曲库、本机随机端口的真实 HTTP 验收：游客「周杰伦 晴天」搜索在开启/关闭重排下均返回 200；`BV1BZbSzZEGT:p1` WBI 音轨 HEAD 返回 200 和 6,201,843 字节长度；`bytes=0-4095` 与 `bytes=100000-104095` 均返回 206、4096 字节及准确 Content-Range。样本 HEAD 约 5.64 秒，后续 Range 约 0.63/0.64 秒；该测量不包含播放器解码与首次声音输出，不代表首播耗时。

本步没有修改界面布局或重新打包安装版，使用源码启动入口体验改动。AI 线上模型和完整窗口听音未在本步重验。

后续已确认的优化点：失效曲目当前会停住队列，可增加有界失败跳过；AI 设置与密钥分别写文件，第二次写入失败可能留下部分更新，需要在设置保存事务中处理。它们不属于本步已交付功能。

## 第二步：推荐与本地连续体验

### 当前行为

- 首页保留“为你推荐”、独立的一句话输入和推荐列表。生成按钮立即切换为“生成中…”并禁用重复提交；失败保留旧列表。刷新忽略输入框，本次输入不进入长期口味数据。
- 无有效 AI 配置且未输入引导时，首页请求 B 站音乐热门榜前 20 条。启用并配置 AI 后，以收藏/歌单摘要和本次输入生成检索词，再重排真实搜索候选；未配置或意图请求失败时使用本地检索方向。候选先结合收藏、歌单和有效听歌记录在本机排序，模型输出只能调整已有 ID 的顺序，不能创建曲目。
- 推荐成功后写入数据目录的 `recommendations.xml`。启动优先读取上次结果，不自动再生成；首次无快照且无 Key 时加载热门榜。首次已配置 Key 则等待用户生成。
- 正常退出保存 `playback-state.xml`，包括队列、当前索引、循环模式和位置。重启只恢复待播放界面，不请求音频、不自动播放；按播放键后加载音频并定位。
- 自动匹配、手动选择及本地 LRC 均缓存到 `lyrics-selections/`，再次播放优先读取缓存，不依赖歌词接口。手动选择优先于自动缓存，校准偏移保留来源。
- 听歌记录继续由本地服务核算实际播放：长度至少 60 秒听够 30 秒，较短曲目听满 90%；暂停与拖动不计入有效时长。原始历史、时间及次数不发送给 AI。
- 设置中的 AI 推荐、数据与隐私折叠收纳，ZIP 导入/导出入口位于数据与隐私。归档包含收藏、歌单、已有听歌记录、非敏感 AI 配置与背景图；API Key 不进入归档，换机后需重新填写。背景文件选择仅在背景图主题下显示，取流标签改为“音频获取方式”。
- 桌宠支持“不显示”，隐藏时不占布局、不运行动画。五类陪伴事件各有八条循环话术，避免同类事件连续重复。

推荐与播放快照采用同目录临时文件原子替换，读取损坏文件时保留原件并显示错误，不用空内容覆盖。当前恢复针对正常退出，不保证进程被强制终止前的最后位置。

### AI 请求与回退

两次请求使用设置中已启用的 HTTPS Chat Completions 地址、模型及 Key。第一次只返回最多四个检索词；第二次只返回真实候选 ID 的排序，不返回歌曲元数据或播放地址。上下文包括收藏/歌单提取的作者、曲名、音乐标签，以及最多 160 字的本次输入；本次输入优先于长期口味，不写入长期画像。

候选请求最多发送 60 条，每条只有 `id/title/artist/durationSeconds`，不发送播放 URL、封面、本地路径或原始听歌记录。候选已按本地口味与相关性排序，提示模型同等匹配时保留此顺序。响应 ID 经请求层与推荐层双重白名单校验，未知 ID 丢弃、重复去除、遗漏按本地顺序补回。

单次 AI 请求默认超时五秒；未配置、超时、网络失败或不合法 JSON 均回退。意图失败保留本地检索方向（包括本次输入），重排失败保留真实候选的本地顺序；AI/B站网络请求不持有个人数据锁。线上服务的模型响应质量尚未实测，验收使用模拟传输和真实本机 HTTP 端点，不产生 AI 服务费用。

### 验收入口

`./scripts/phase3-smoke.ps1` 创建全新的隔离数据目录和本机 HTTP 桩，执行两轮真实 JavaFX 启动，检查不自动播放、播放定位、缓存歌词、推荐保存/加载反馈与设置，并输出首页和小窗口截图。不访问个人曲库，不依赖在线 AI。

`./scripts/phase3-installed-smoke.ps1 -InstalledHome '安装目录' -Java '<完整JDK>/bin/java.exe'` 对安装 JAR、依赖及 VLC 执行相同隔离检查，并验证类加载来源。jpackage 剥离命令行 Java 启动器时须显式传入开发机已有 JDK；安装 EXE 的内置运行时另通过实际启动、健康接口及正常退出验收。本机安装版已包含以上改动，安装与数据保留结果见[验收记录](VALIDATION.md)。

`./scripts/installed-online-smoke.ps1` 专门检查安装目录的真实 B 站在线播放，包含链接搜索双击、暂停恢复、切歌和收藏双击，以 VLC 时间实际推进为判据；Python、Axum 和所有状态均隔离，结束清理自有进程与端口。可用 `-InstalledHome`、`-Python` 指定当前安装目录和实际解释器。

取流的分页、WBI 密钥和签名 playurl 采用匿名优先，风控拒绝后补完整游客票据并有界重试，不再强制依赖 B 站首页可达。搜索仍检查两张票据，主页失败可通过 SPI 补齐。不同音轨的解析只在缓存读写时持锁，Axum 到本机 Python 的转发不使用环境代理。

## 网络与窗口交互

B 站 API 与音频 CDN 默认直连，传输失败时在原有超时预算内尝试当前系统代理；每次请求重新读取代理配置，配置变化时清除路由偏好。成功路由按站点记忆，代理失效时也可回到直连。HTTP 风控拒绝不切换网络，TLS 验证保持启用。此策略不修改系统代理，AI 请求仍使用原有独立链路。

安装版在线验收可传 `-NetworkScenario DirectOnly` 或 `UnavailableProxy`，仅在测试进程内模拟无代理/失效代理，不需要改动系统设置。

无边框主窗口支持四边四角拖动缩放，靠近边缘显示方向光标；最小尺寸为 860×600，最大化时禁用边缘拖动。底栏、搜索、收藏/歌单动作和沉浸页随可用空间调整，字号不随窗口缩放；长标题可换行或省略，设置保持滚动可达。

## 播放体验扩展

- 迷你播放器的标题、封面和空白区域长按约 300 毫秒后可拖动；按钮、滑块和输入控件仍执行原有操作。
- 设置 → 音频提供本地音频缓存，默认关闭、默认上限 512 MiB。完整下载后才进入持久缓存；命中缓存直接播放本地文件，不再预检音源。容量可调，超过容量按最近使用时间淘汰，可随时清空；清空或关闭不会让正在下载的旧任务重新填入缓存。
- 同一处可开启响度归一化。VLC 静音分析器测量曲目开头约 20 秒，按 K 加权与门限计算响度，调整真实音频增益而不改音量滑块。目标为 -18 LUFS，增益限制为 -12 至 +7.9 dB，并保留峰值余量。首次测量需要等待，结果在本次运行中复用；不是整首扫描。
- 分 P 列表可标记“不想听”或恢复；顺序、随机和循环均跳过这些分 P。全部排除时不继续播放，原列表仍可用于恢复。粘贴完整 BV 号会开始播放并展开完整分 P 列表。
- 设置 → 快捷键可录制上一曲、播放/暂停、下一曲及音量增减的组合键；后台同样有效。录制期间暂停旧注册，冲突会提示，退出时释放注册。
- 播放失败在主界面各页面与迷你播放器展示原因。只有确认已删除、分 P 不存在、没有可用音轨或本地文件缺失等永久故障才标记失效；暂时超时不会成为清理目标。设置 → 数据与隐私可清理收藏及所有歌单中的失效条目。
- 我的歌单可导入公开 B 站收藏夹，最多导入 200 首有效且不重复的歌曲；跳过失效项，并提示是否达到上限。整个解析有 120 秒预算，超时不写入半成品歌单。
- 侧栏右边界可拖动，窄到阈值自动成为图标模式，底部按钮也可收起或展开；状态随本地设置保存。沉浸页使用更大的 16:10 封面和歌词上下渐隐；列表标题加粗，真实播放量与时长靠右对齐，未知播放量不虚构。首页间距收紧，窗口控制图标统一。

网络自动重试只针对暂时传输故障，次数和总时间都有上限；已删除、权限拒绝、无音轨等明确错误不会反复请求。切歌与取消仍使用请求身份检查，旧结果不能覆盖新曲目。

`./scripts/player-feature-smoke.ps1 -Smoke Feature` 执行隔离数据的真实 JavaFX 交互检查；`-Smoke Cache` 使用真实 AAC 与 VLC，验证首次完整缓存、重启后离线回放和零音频网络请求。增加 `-InstalledHome '安装目录'` 可对安装 JAR 执行相同检查并核验类加载来源。
