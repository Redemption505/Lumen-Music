# 第三阶段：拓展与整合

本文是 Lumen Music 第三阶段的项目说明与验收依据。基线为 v0.1.1 歌词修复版；3.1–3.12 已完成实现、测试与整体验收，全部纳入 v0.2.0 本机安装版及 Windows x64 发行包。实际结果、对应源码与更新证据见[第三阶段整体验收](PHASE3_ACCEPTANCE.md)；各步骤记录见[验证结果](VALIDATION.md)。

前期应用逻辑与功能优化见 [v0.1.1 基础说明](PHASE3.md)，现有实现入口见 [README](../README.md)。本阶段沿用 JavaFX、Python 与 Rust Axum 的现有分工，具体接口和数据格式在对应步骤实施前确定。

## 1. 阶段目标

让用户在 B 站和本地文件中找到的音乐，能够持续积累成容易播放、整理和重新发现的个人曲库。

本阶段重点解决三个问题：

- 资源组织：长视频中的单首歌曲、多 P、现场与翻唱版本，都能清楚地收藏和管理。
- 连续听歌：队列行为可预期，推荐可以调整，旧收藏也有机会被重新发现。
- 个人体验：日常浏览、沉浸听歌和专注陪伴各有合适的界面，数据和偏好能持续保留。

现有游客搜索与取流、收藏和歌单、缓存、有效听歌记录、真实候选 AI 推荐、歌词匹配、播放恢复、桌宠、迷你播放器及安装更新流程，是本阶段的基础。新增功能应接入这些能力，共享播放状态。

## 3. 核心功能

### 3.1 片段歌曲：单独收藏长视频里的一首歌（已实现）

示例：将一个两小时合集中的 `18:32–22:46` 保存为《美人鱼》，以后可以直接收藏、加入歌单、随机播放和单曲循环。

已交付范围：片段创建、编辑、删除、试听与持久化；独立身份与来源时间区间；相对进度、终点单次结束、单曲循环回到片段起点；本地与在线源的拖动定位；歌词按片段时间轴显示并独立保存偏移与起点；有效听歌记录按片段时长计算；同源片段共享音频缓存；重启恢复；加入收藏与歌单。裁剪导出和带时间戳曲目表导入仍属于后续范围。

首版流程为：打开源曲目 → 设置起止时间 → 填写歌名及可选歌手 → 试听 → 保存为歌曲 → 加入收藏或歌单。

- 支持从当前播放位置标记起点和终点，也能直接输入时间；保存前校验起点非负、终点晚于起点，并在源时长已知时校验边界。
- 片段有独立身份，记录来源和时间区间。同一 BV、同一 P 中的不同片段可以分别收藏；普通整曲继续按原方式使用。
- 播放进度和时长以片段为单位。到达终点只执行一次结束动作；单曲循环回到片段起点，顺序播放进入下一曲。
- 歌词按片段时间显示，歌词自身的偏移与片段起点分别保存；手动匹配和缓存继续有效。
- 播放恢复、听歌记录和缓存理解片段身份。有效听歌阈值按片段时长计算，暂停和拖动不计入实际收听时长。
- 首版保存来源引用与时间范围，复用源音频缓存。裁剪导出音频不属于首版范围。

后续可增加带时间戳曲目表的粘贴导入，以及视频章节、简介目录的解析预览。解析结果需能检查和修改，AI 不凭空生成歌曲边界。

### 3.2 版本管理：歌曲与播放资源分开组织（已实现）

歌曲详情提供“版本”入口，收纳录音室、现场、翻唱、纯音乐及不同上传资源。用户可以指定偏好版本，也可以独立保留某个版本。

- 歌曲层保存个人标题、备注和收藏关联；版本层保存具体演唱信息；资源层保存 BV/P、本地文件或片段来源。
- 自动分析仅给出可能重复或相关的候选，合并与拆分可由用户确认和撤销；不同歌手的翻唱不自动当作完全相同的录音。
- 资源失效时提供替换候选。确认替换后保留歌单位置和个人备注；歌词校准、时长和缓存按新资源重新核对。
- 已实现手动建立歌曲、添加真实资源版本、版本信息编辑、首选版本、指定资源播放、独立收藏、拆分与合并、资源替换和单步撤销。当前播放保留快照；替换更新尚未播放的队列条目，不打断音频。
- 关联候选由本机标题规则提示，不自动合并；歌曲和版本随现有曲库保存与 ZIP 恢复。歌曲行菜单、沉浸页及收藏页提供入口，操作细节见[歌曲版本管理](SONG_VERSIONS.md)。

### 3.3 私人电台：持续推荐，并允许用户纠正（已实现）

从当前歌曲、歌单或一句话开启电台，例如“继续听这种安静的女声”。

- 提供“熟悉一些 / 多发现一些”的偏好调节；优先在本机结合收藏、有效听歌记录与真实检索结果组织候选。
- 增加“暂时听腻了”“少推荐这个版本”“本次不影响口味”等反馈，并提供查看和恢复入口。
- 降低近期重复，减少同一歌手连续出现；跳过一次仅作为弱信号，不直接判定永久不喜欢。
- 推荐理由来源于实际依据，例如“来自你最近常听的钢琴歌单”。候选不足时明确说明，不伪造歌曲或理由。
- 推荐补充位于手动安排之后，用户可以预览、移除和关闭自动续播；正在播放的歌曲不因推荐刷新而变化。

AI 继续只生成意图与重排真实候选，模型返回的未知曲目 ID 不进入曲库。沿用现有数据发送边界，原始听歌记录和本地路径不上传；本次引导与长期偏好分开保存。缺少 Key 或请求失败时仍能使用本地规则。

已交付：首页、歌曲行、歌单与沉浸页入口；熟悉/发现模式、待播预览与真实推荐依据；移出本次、手动安排优先、自动补充及关闭续播；七天临时排除、版本降权、弱跳过反馈与恢复；反馈重启和 ZIP 恢复；中立模式不使用长期口味、不计入听歌记录。已知演唱者用于相邻多样化，其他资源按作者处理，不将 UP 主当作已知歌手。单曲循环仍优先；普通列表重新选曲退出电台。操作见[私人电台](PRIVATE_RADIO.md)。完整队列分层、批量撤销及导航保留仍归 3.5。

### 3.4 智能歌单：按规则整理曲库（已实现）

支持保存筛选规则并自动更新结果，例如“收藏超过一个月但最近没听过”“已缓存的纯音乐”“八分钟以内的现场版”。

- 首版规则基于确实存在的字段和记录：收藏时间、最近收听、缓存状态、时长与用户标签；缺失信息不被当作已知信息。
- 支持手动标签、歌单文件夹、批量编辑与重复候选整理；自动建议的标签允许纠正。
- 智能歌单标明规则，可编辑规则，也可另存为普通歌单。
- 规则变化只更新展示结果；已建立的播放队列保留自己的快照，避免浏览或筛选打断播放。

已交付：收藏及歌单页整理入口、组合规则与预设、动态预览、普通歌单快照、批量标签、可修正的本地建议标签、歌单文件夹及重复候选到版本管理的衔接。缓存按本机完整文件判断，缺失日期或时长保持未知；播放保留筛选出的具体版本和片段。规则与整理信息随原有 ZIP 备份保存。操作见[智能歌单与曲库整理](SMART_PLAYLISTS.md)。

### 3.5 队列与导航：操作结果可预期（已实现）

- 队列区分“手动安排”“当前歌单后续”“电台推荐”。手动安排优先，自动推荐不会挤到它前面。
- “下一首播放”将曲目放到当前歌曲之后；连续执行时，以最近一次操作为下一首。“添加到队尾”追加到当前已安排队列末尾、自动推荐之前。
- 手动拖拽体现用户指定顺序，随机模式不立即重排手动安排；移除当前歌曲选择可用后继，无后继则选择前项，并保留原来的暂停状态。
- 返回歌曲列表时保留滚动位置、筛选条件和选中项；窗口缩放、切换播放页不重建队列。
- 移出歌单、清空队列等操作提供撤销，撤销后恢复原顺序；批量操作保持统一含义。
- 应用内 Ctrl+K 快捷搜索同时查找歌曲、歌单与常用操作，输入文字时不误触播放快捷键。

已交付：队列来源标识与恢复、下一首/队尾批量安排、随机手动优先、未来项显式拖拽顺序、按条目移除和队列撤销、普通歌单批量移除与原序撤销、歌单浏览位置及选择保留、沉浸/设置返回原页、应用内 Ctrl+K 快捷搜索及输入保护。删除当前项选择可用后继，无后继则选择前项，原来暂停时保持暂停；删除全部可用项或清空会停止播放和电台续播。队列撤销不覆盖后续切歌/模式变化；歌单撤销不覆盖目标歌单的后续修改。操作见[队列与导航](QUEUE_NAVIGATION.md)。

### 3.6 统一视觉与播放场景（已实现）

建立稳定的背景、内容、悬浮菜单三个视觉层级，统一文字对比度、间距、圆角、阴影、图标和交互状态。透明效果服务于层次与可读性。

| 场景 | 主要内容 | 交互重点 |
| --- | --- | --- |
| 日常浏览 | 紧凑歌曲列表、版本与来源信息 | 扫描、筛选、批量整理、行内操作 |
| 沉浸听歌 | 封面、歌词与必要播放信息 | 控件随操作显现，封面在底栏与沉浸页之间连续过渡 |
| 专注陪伴 | 精简曲目信息、可选计时器、低干扰桌宠 | 专注结束提示、睡眠定时、减少无关动态 |

队列从侧边平滑进入，歌词居中跟随，切歌时主题色缓慢过渡。动画可被连续操作打断，不能阻塞播放或产生重复窗口；提供减少动态效果的选项。各场景使用同一播放状态，继续适配最小窗口和高 DPI。

已交付：五种主题的背景、内容与菜单层级，紧凑歌曲列表；底栏与播放页的封面位置及裁切过渡、沉浸控件闲置淡出与操作显现、可中断队列动画及当前歌词居中；共享原播放器的专注陪伴页、专注倒计时、睡眠定时和安静桌宠；本机持久化的减少动态偏好。专注完成只提示，睡眠到时暂停播放并停止电台自动续播；返回保留原浏览页面。真实窗口已验证 860×600、1280×800 及 125%/150% 缩放。操作见[视觉与播放场景](PLAYBACK_SCENES.md)。

### 3.7 最近播放与桌宠整合（已实现）

将本地听歌记录转化为可以回看的内容，例如“上周第一次听到的歌曲”“最近重新播放的老收藏”“本月常听歌单”。支持私人备注和歌词片段收藏。

- 统计依据实际记录，区分音源、片段与歌曲，避免将一个长视频虚构为多首已听歌曲；数据不足时展示相应空状态。
- 日记在本机生成，可随个人数据备份导出和恢复；分享由用户主动触发。
- 桌宠对真实事件回应，例如重听老收藏、完成专注、收藏新曲；为提示设置频率上限，减少重复。
- 专注与夜间场景降低动作和提示强度，尊重隐藏桌宠和减少动态效果的设置。

已交付：本机有效播放事件、准确的自然周/月回顾、真实歌单来源、老收藏重听、音源/曲目/已关联歌曲分别计数；侧栏日记入口与回顾/备注/歌词三视图、歌曲行私人备注、歌词单句/多句收藏；本机 Markdown/文本主动导出及原有 ZIP 备份恢复。未知旧日期保持未知，私人内容不进入模型请求，编辑不打断音乐。桌宠在真实收藏成功、有效重听及专注完成后低频回应，主窗口与最小化桌面窗口均可显示，隐藏后清理提示；夜间和减少动态停止动作。真实音频、五种主题、最小窗口及 125%/150% 缩放已验收。操作见[最近播放与桌宠](MUSIC_DIARY.md)。

## 4. 第三阶段尾声

3.1–3.7 核心范围及以下 3.8–3.12 收尾路线已按顺序完成，统一交付为 v0.2.0。

### 3.8 精听与练习：从听一首歌到反复听喜欢的一段（已实现）

- 点击同步歌词跳转到对应位置，兼容歌词起点、校准偏移、长视频片段及多 P；跳转保持当前播放或暂停状态。
- 最近播放中的收藏歌词直接播放关联曲目，并定位到收藏时保存的曲目相对位置。
- 支持 A–B 起终点标记、时间编辑、启停和清除；范围不得超出当前曲目，切换曲目清空临时循环。
- 循环可保存为新的片段歌曲，复用现有试听、收藏和加入歌单流程；已有片段的相对 A–B 范围换算为源音频时间。
- 提供 0.75×、1×、1.25×、1.5× 播放速度。使用现有引擎能力，明确不同引擎的音调处理；重启恢复普通速度。
- 循环优先于普通队列推进；暂停、拖动和变速不虚增有效收听时长，同一收听会话不重复入账。长歌需实际听够 30 秒，短歌按真正播放的媒体进度达到 90% 判断，记录的秒数仍是实际收听时间。

验收：歌词时间逆变换、片段边界、暂停跳转、循环与清除、快速切歌、速度实际推进、有效收听计时，以及最小窗口、各主题和高 DPI 的可读性。

已交付：底栏、沉浸页和 Ctrl+K 练习入口；两处同步歌词单击定位、日记收藏歌词直达；当前曲目相对 A–B 标记、编辑、启停及清除，片段终点循环优先于队列；循环范围保存为新的片段歌曲；四档实际变速、跨曲保留和重启恢复 1×。手动跳到范围外暂停循环，换曲清空临时标记；同一会话多轮循环只入账一次。真实 JavaFX/VLC、五种主题、860×600/1280×800 和 125%/150% 缩放已验收。操作见[精听与练习](PRACTICE.md)。

### 3.9 连续播放优化：减少等待，改善切歌听感（已实现）

- 根据真实队列预加载下一曲，优先使用完整缓存；手动插队、拖动、切换电台后取消过时任务。
- 预加载不产生收听记录、不把未播放资源误标失效，也不允许旧请求覆盖当前播放。
- 增加可选的短淡入淡出；先完成预加载，再评估需要双音轨的交叉淡化。
- 网络等待和重试反馈统一，缓存容量和用户设置继续生效。普通淡入淡出、交叉淡化和无缝播放分别评估，不以网络音源零等待作为承诺。

验收：实际切歌等待改善、缓存与取消、快速切歌、音量与归一化、网络波动及手动队列优先级。

已交付：默认开启、可取消的下一真实后继准备，随机后继保留和手动队列优先；完整缓存复用及同源片段共享、未播放文件不持久化或入账、不误标失效；统一有限重试与等待反馈；默认关闭的短淡入淡出、变速与练习隔离。JavaFX 缓存播放使用会话副本，播放中清空持久缓存不打断音乐。真实双引擎、125%/150% 缩放已验收，合成慢连接场景切歌等待减少约 1.25–1.38 秒；不代表公网固定时延或无缝播放保证。操作见[连续播放](CONTINUOUS_PLAYBACK.md)。

### 3.10 合集批量整理：把长视频更快变成自己的歌单（已实现）

- 粘贴带时间戳和歌名的曲目表，生成可编辑的片段候选，显示起止时间、时长并逐段试听。
- 用户确认后批量加入收藏或生成普通歌单；校验源边界、重复条目和未知终点。
- 后续接入确实存在的视频章节、简介目录；没有可靠边界时保留待确认状态，AI 不猜测歌曲边界。

验收：时间格式、顺序和边界、预览修改、批量保存与失败反馈、源缓存共享，以及播放队列不受整理操作影响。

已交付：歌曲行与沉浸页入口、最多 200 条本机时间戳解析、即时编辑校验、勾选保存和真实逐段试听；相邻有效起点或已知源尾补齐终点，未知边界保留待确认。确认后原子加入收藏或新普通歌单，同源同范围收藏跳过，失败保留草稿并支持幂等重试。试听结束恢复原队列、位置和播放状态，不写收听记录或消耗电台候选；保存不打断音乐。缓存共享、重启及 ZIP 恢复、深浅主题和两档 DPI 已验收。操作见[合集批量整理](SEGMENT_BATCH.md)。

### 3.11 更新与反馈：让测试者方便持续使用（已实现）

- 应用内选择本地更新包，核对适用版本、退出后更新，保留个人数据并提供更新失败的恢复路径。
- 导出本机诊断信息，包括应用版本、播放引擎和近期错误；排除 API Key、私人备注及原始个人记录，由用户主动分享。
- 设置中显示版本、构建标识和本版更新内容，便于核对反馈。
- 在线检查更新在确定稳定分发地址后接入，不作为本轮前提。

验收：旧版升级、错误包拒绝、数据保留、失败恢复、诊断内容及版本与实际构建对应。

已交付：设置中的实际版本、构建标识与更新说明；安装版选择本地 ZIP、适用版本与程序/运行环境校验、明确确认后退出更新；可信内置更新器等待原进程退出、备份实际原文件、逐文件核验及失败恢复结果。诊断只导出版本、引擎状态、开关与固定错误代码，不读取原始日志或私人数据；不会自动上传。逻辑、隔离更新/回滚、真实系统文件选择及两档 DPI 已验收，真实 v0.1.1 → v0.2.0 发行包升级归 3.12。操作见[本地更新与诊断](UPDATES_FEEDBACK.md)。

## 5. 实施顺序

| 轮次 | 范围 | 完成标志 |
| --- | --- | --- |
| 第一轮：建立特色 | 片段歌曲、必要的数据衔接、队列与导航规则 | 合集中的一首歌可以独立保存、播放、循环和恢复，手动队列行为稳定 |
| 第二轮：整合曲库 | 版本管理、智能歌单、私人电台 | 收藏、缓存、标签和听歌记录共同参与整理与发现，反馈可以纠正 |
| 第三轮：个人体验 | 统一视觉、最近播放、桌宠场景 | 三种播放场景连贯可用，个人回忆与陪伴有真实依据 |

基础可读性和交互缺陷随每轮修复；第三轮负责完整视觉整合。核心完成后按 3.8 → 3.9 → 3.10 → 3.11 → 3.12 执行尾声路线；手机遥控继续依据使用反馈排期。

第一轮按以下步骤推进，每一步完成对应验证后再进入下一步：

1. 核对现有 Track、曲库、队列、歌词和播放快照的数据关系，确定片段身份及旧数据读取方案。已完成。
2. 实现片段创建、编辑、删除、试听和持久化，允许将片段加入收藏与歌单。已完成。
3. 接入片段播放边界、相对进度、循环、切歌、歌词和重启恢复。已完成。
4. 接入有效听歌记录、缓存共享与数据备份恢复。已完成。
5. 统一手动队列规则、撤销和页面返回状态，完成端到端验收。已完成（见 3.5）。

本阶段全部功能已同步源码、本机安装版及 v0.2.0 发行包。后续扩展以实际使用反馈为依据，不再将已交付功能列为待安装。

## 6. 验收要求

以下为本阶段验收标准；实际执行结果逐项对应[整体验收报告](PHASE3_ACCEPTANCE.md)，不以标准本身替代测试证据。验证覆盖纯逻辑、数据读写、真实播放器和实际界面。

| 范围 | 必须验证的行为 |
| --- | --- |
| 片段播放 | 在线与本地源的起止边界、相对进度、暂停恢复、拖动、单曲循环；终点事件只处理一次，快速切歌不串台 |
| 歌词 | 普通整曲、多 P、长视频片段均使用正确时间轴；手动匹配与缓存保留，旧请求不能覆盖新曲目 |
| 队列 | 手动安排优先、连续“下一首播放”、队尾追加、随机、删除及撤销的顺序符合定义 |
| 个人数据 | v0.1.1 收藏、歌单、歌词与配置能读取；新增数据重启和 ZIP 恢复后完整；损坏文件不被空数据覆盖 |
| 缓存与网络 | 同源片段共享缓存，缓存命中可离线播放；临时网络失败不误标永久失效，取消任务不污染当前播放 |
| 推荐与规则 | 候选都来自真实资源；用户反馈生效且可恢复；无 Key 可用，规则刷新不改变当前队列 |
| 界面与陪伴 | 最小窗口、常用大窗口、高 DPI 与各主题可读；菜单不裁切、文字不重叠；连续操作与减少动态效果可用 |
| 分发 | 发布时核对安装包与源码对应关系，验证旧版更新、本机安装版运行及个人数据保留 |

发布前保留可恢复的数据与旧发行包，完成针对本次变更的验收。文档中的状态只有在功能交付并验证后才更新为“已完成”。
