## 3. 启动观测与限制

同一开发机 Windows 11 x64，使用原资料且保持日常网络和安全软件配置，未重新启动系统或清理缓存。每轮正常退出并确认进程释放后，至少等待 30 秒再启动；前置核对和人工操作使实际间隔有所增加。五次应用启动均成功。

| 从原生启动动作计时的观察点 | 中位数 | P90 / 最大值 |
| --- | --- | --- |
| 首次观察到窗口句柄 | 13009 ms | 15796 ms |
| 自有 Python 健康 | 15870 ms | 28332 ms |
| 自有 Rust 代理健康 | 15871 ms | 32109 ms |

窗口句柄出现不是首帧绘制。轮询还包括进程、模块及协议核对，数字包含观察开销。原生输入和页面截图用于确认响应；工具调用与截图耗时不是产品操作延迟。没有得到统一精确的 UI 就绪或退出耗时分布，不将这些功能结果填成完整 CSV 性能预算验收。五样本的最近秩 P90 等于最大值；启动等待仍明显且存在波动。

系统重启后的首启、新资料首启、独立电脑及原闪退者仍按 [启动方案](STARTUP_ACCEPTANCE.md) 另验；本机五次成功不能认定原朋友的闪退原因已经解决。工程旧/新对照和缓存组件计时继续见 [稳定性验收](PHASE4_STABILITY_ACCEPTANCE.md)。
