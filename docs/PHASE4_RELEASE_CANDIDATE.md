## 3. 测试入口与恢复

基本检查仍使用 [开发与复现](DEVELOPMENT.md) 的 `launch.ps1` / `check.ps1`。D 修正了 `check.ps1` 在 Python 单元测试期间全局路径覆盖干扰测试临时目录的问题，仍保留隔离用户目录及调用结束后的环境恢复。

`candidate-endurance-smoke.ps1` 显式接收目标 `AppHome`、Java 和 Python，可独立编译已声明的测试驱动，验证本地长听、在线 20/10 及 `-PublicSegments`；所有资料留在指定工作区证据目录。`playback-scene-smoke.ps1` 明确拒绝比源码旧的测试类，并记录驱动及应用身份；`DiaryStartupSmokeLauncher` 验证启动读取和恢复。它们需要完整 JDK，属于开发验收入口；安装用户使用包内运行环境即可。

本轮还确证 PowerShell 7/.NET 10 的空值绑定差异：直接向 `SetEnvironmentVariable` 传 `$null` 会使子 Java 收到空字符串。私有原生探针曾由此传入空 provider，正式入口正确拒绝后出现通用 JVM 错误。已用真实 Java 子进程及正式入口受控复现，改为删除 `Env:` 项；这是验收脚本的问题，没有修改播放器来绕过校验。相关公开入口在恢复缺省环境时也改为真正删除，PS5/7 分别验证，原失败证据保留。

真实安装版在常规环境正常启动、使用并退出后，再以仅含 Windows 的 PATH 启动；后一次首次观察到窗口约9.61秒，服务及代理就绪约11.78秒，正常关闭后包括控制台宿主在内的六个记录进程均退出。原探针的十分钟观察期先结束，因此保留原 `pending` 记录，另附本轮原生关闭和进程身份核对；没有将其改写为探针捕获了退出码。上述是本机首轮及后续启动观测，没有重启操作系统测量严格冷启动，也没有建立跨机器性能预算。

归档验收脚本仅补充 UTF-8 BOM，使现有 Windows PowerShell 5.1 正确读取中文文件名；正文、验证范围及断言不变，与 PowerShell 7 分别核对实际归档。

旧 `.4` 完整/增量包、安装文件和个人资料已保留在本机私有恢复目录，未经上传。实际增量验收在工作区的旧镜像副本执行，验证成功更新、失败拒绝和回滚后原字节与资料保留。
