# 本地更新与诊断

设置 → 版本与反馈显示当前 JAR 的版本、构建标识及本版更新内容。安装版可以选择本地更新 ZIP；源码运行不提供程序文件更新入口。

当前 v0.2.2 修复构建是 `lumen-0.2.2-20261007.4`。已安装早期 v0.2.2 时运行完整包的安装器升级，沿用原安装目录并保留个人资料；v0.2.1 → v0.2.2 增量包供 v0.2.1 使用。安装目录和开始菜单的“卸载 Lumen Music”直接使用 Windows 缓存的安装登记，下载的安装 EXE 可以移走或删除。详情见[Windows 安装与卸载](WINDOWS_INSTALLER.md)。

## 本地更新

选择包后核对适用版本、目标构建、保留的运行环境和载荷大小/SHA-256。只有确认“更新并重启”才启动当前程序内置的更新工具；不会执行 ZIP 中自带的脚本。

更新工具等待播放器及其内置服务正常退出，再备份实际原文件、替换清单中的程序文件并核验结果。曲库、歌词、设置和缓存不属于更新载荷。失败时尝试恢复，分别记录未改动、已恢复或恢复失败；再次打开播放器可以在设置查看结果与备份位置。

v0.1.1 原版、歌词热修及本机阶段构建共用版本号，本次不要求它们具有同一个旧 JAR 哈希；来源版本和不变的内置运行环境必须匹配。v0.1.1 尚无应用内更新入口，首次升级至 v0.2.0 使用更新包中的 `update.cmd`。完整安装程序也可直接升级。

更新包复用绝大多数运行环境，Python/VLC 无需重新安装；`runtime/lib/modules` 随包更新，统一旧安装版与便携版的 Java 镜像差异，其余运行环境仍逐文件严格匹配。原 Java 镜像与程序文件一同备份，失败时恢复。Windows 安装登记的版本可能保持原值，运行完整安装程序才同步登记；应用内版本来自正在运行的 JAR。没有配置在线检查更新或自动上传。

## 诊断导出

“导出诊断信息”由用户主动选择文件位置，生成只有 `diagnostics.txt` 的 ZIP，包含当前版本/构建、操作系统类型与架构、Java 版本、播放引擎及状态、有关功能开关、最近最多 20 条错误的 UTC 时间和固定代码。

不读取原始服务日志、API Key、私人备注、收藏或歌单内容、原始听歌记录、本地路径和背景图。未知错误归为 `UNKNOWN_ERROR`，原始消息不写入诊断记录。诊断记录损坏时保留原文件，不以空记录覆盖。

诊断与个人备份是不同的文件：前者用于由用户主动分享问题信息，后者含个人数据，仅用于数据迁移和恢复。
