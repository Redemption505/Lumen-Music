# Lumen 视觉语言

本文对应[第四阶段 §3.1](../第四阶段.md)的桌面实现。首轮覆盖首页、普通歌单、沉浸播放和设置；实际测试范围见[验收报告](PHASE4_VISUAL_ACCEPTANCE.md)。

## 风格与主题

Lumen 采用暖墨底色、暖金强调与低饱和封面柔光。浅色主题采用暖白底色；深色主题保留中性墨色。背景图和动态背景沿用相同的文字、面板、按钮及弹层规则。

五档主题保持不变。在“设置 → 外观与动效”中切换主题、强调色和减少动态效果；背景图选项仅在背景图主题显示。Lumen 固定暖金，其他主题继续提供六种强调色。

| 角色 | 显示规则 |
| --- | --- |
| 背景 | 营造氛围，封面色限制饱和度和亮度 |
| 内容面板、输入框、列表 | 提供稳定阅读底色，不随封面变成高饱和色块 |
| 正文、次要文字 | 歌名突出，演唱者和来源降低视觉权重但保持可读 |
| 强调色 | 用于播放、选中和焦点；文字与按钮前景分别选择可读颜色 |
| 收藏 | 已收藏显示红心色，列表、底栏和沉浸页保持一致 |
| 弹层、错误 | 弹层使用不透明底色；播放错误使用独立提示色 |

## 封面和曲目身份

歌曲行、底部播放栏及沉浸页均按原始比例完整展示封面，剩余区域使用画框底色。宽图与竖图不拉伸；沉浸页保留适合宽封面的画框，不强制裁切为正方形。

缺图统一使用音乐符号占位。底栏和沉浸封面的悬停提示区分无图、加载中和暂时失败；封面失败仍可继续听歌，重新打开所在歌单可重试已有资源。

歌曲行和沉浸页优先展示用户整理的歌名。已有歌曲版本的演唱者与版本标签次之；未整理的 B 站资源明确显示“UP 主”，不会自动把上传者当歌手。来源、BV/P 与片段边界保留在来源提示中，长标题可通过悬停查看全文。窄窗口不会把已整理的演唱者覆盖回资源作者。

## 操作和状态

红心表示收藏，更多菜单承载次要操作。悬停使用统一背景，键盘焦点使用可见边框，聚焦时按钮尺寸保持稳定；不可用操作降低亮度并停止接收操作。沉浸页与底栏的收藏颜色及提示同步。

首页的整理与最近播放辅助按钮使用透明背景、次要文字和细边框，常驻歌单使用输入区域底色；悬停提高文字与背景对比，聚焦保留主题焦点边框。歌单操作栏统一圆角与内边距，迷你窗口的返回按钮沿用相同焦点规则。

首页推荐空态说明如何生成推荐，空歌单说明如何加入曲目，无歌词说明如何匹配且不影响继续播放。歌单操作结果就近显示，长反馈可以换行。

设置首先展开“外观与动效”，桌宠与专注相关选项放入“桌宠与陪伴”；原有音频、快捷键、AI、数据与版本设置继续保留。

## 动效与播放连续性

封面画框过渡为 220ms，封面色调使用约 240ms 的短过渡。减少动态效果即时停止动态背景与过渡，保留导航、队列和播放操作。

页面、曲目/版本列表、片段表、备注文本框和下拉列表的离散滚轮输入采用累积平滑移动。嵌套滚动由内层控件接收，反向滚动立即响应；滚动条拖动、键盘和原生触控板手势保留直接操控。普通与沉浸歌词共用约 400ms 的平滑居中，超长行平滑跟随媒体时钟；暂停与跳转保持同步。“减少动态效果”即时停止这些过渡。

浏览歌单、展开沉浸页再返回沿用同一播放器和队列，恢复浏览页及滚动位置，不重新载入歌曲。

## 复验入口

先使用项目已有 Maven 环境完成 `desktop/` 的 `test-compile`，再从项目根目录运行：

```powershell
./scripts/visual-language-smoke.ps1 -AppHome '<目标应用镜像>' -Java '<完整JDK的java.exe>' -Profile All
# 当前源码验证，显式提供含依赖 JAR 和 vlc/ 的既有运行时：
./scripts/playback-scene-smoke.ps1 -RuntimeHome '<既有运行时目录>' -Java '<完整JDK的java.exe>' -Python '<Python解释器>' -SmokeLauncher com.lumenmusic.VisualLanguageSmokeLauncher -ArtifactDirectory visual-language-smoke -Profile All
```

视觉脚本使用隔离曲库、合成 WAV 和本机 HTTP 封面，不写入个人资料。依赖与目标由上述参数明确指定；缺少文件时明确报错，不自动安装工具。`Normal` 使用系统当前缩放，`HiDpi` 强制 150%，`All` 顺序运行两者。视觉场景还检查实际歌单操作栏样式和五主题迷你窗口的内部 Shift+Tab 焦点、悬停/禁用样式，以及返回后播放器实例、队列和播放状态保持；首页辅助/常驻/侧栏的样式由 `PersonalHomeSmoke` 检查。状态伪类检查不改业务绑定，内部场景事件不等于原生鼠标键盘接管验收。运行参数及源码来源边界见[开发与复现](DEVELOPMENT.md#4-windows-场景与历史-fixture)。

焦点像素检查必须区分 Scene 的焦点所有者与窗口/控件实际输入焦点。当前驱动只在窗口激活、起始控件聚焦且目标未聚焦时取基准；遍历后确认目标实际聚焦，刷新 CSS/布局再比较边界像素与尺寸。失焦与真正缺边框分别报错，原阈值不降低；受控负向场景及同一生产 JAR 双缩放结果见[焦点专项验收](FOCUS_VISUAL_ACCEPTANCE.md)。定向复现可使用 `VisualFocusSmokeLauncher`，不能代替完整页面矩阵。
